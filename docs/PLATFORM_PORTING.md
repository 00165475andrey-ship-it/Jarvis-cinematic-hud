# Платформенная совместимость J.A.R.V.I.S. Desktop

Этот документ фиксирует фактическую поддержку платформ и порядок расширения проекта. Он не объявляет платформу поддерживаемой только на основании успешной компиляции.

## Текущий статус

| Платформа | Приложение | Vosk runtime | Статус |
|---|---|---|---|
| Windows 10/11 x64 | Win32 API | официальный Windows x64 DLL | Основная цель; CI-сборка есть, требуется проверка на реальном ПК и микрофоне |
| Windows 7 SP1 x64 | Win32 API с целью Windows 7 | тот же Windows x64 DLL | Экспериментальная цель; CI-сборка есть, запуск DLL и микрофона нужно проверить на реальном ПК |
| Windows x86 (32-bit) | отдельная сборка не настроена | в используемом официальном релизе Vosk 0.3.45 отдельного Windows x86 runtime asset нет | Не поддерживается |
| Linux x86_64 / ARM64 | текущий интерфейс использует Win32 API | у Vosk есть отдельные Linux runtime архивы | Не поддерживается приложением |
| macOS Intel / Apple Silicon | текущий интерфейс использует Win32 API | macOS runtime не включён в используемый набор официальных архивов Vosk 0.3.45 | Не поддерживается |

## Почему одного Vosk недостаточно

Распознавание речи — только одна часть приложения. Основной интерфейс и системные панели используют Win32, WinMM, Windows Performance Data Helper, IP Helper, Power API и другие Windows API. Для Linux и macOS нужно заменить не только DLL Vosk, но и оконный интерфейс, захват микрофона, системные показатели, горячие клавиши, запуск приложений и системные действия.

## Порядок портирования

1. Выделить независимое ядро голосовых макросов: модель данных, JSON-разбор, точное сопоставление команд, настройки и журналирование.
2. Ввести платформенный интерфейс для аудиозахвата, загрузки Vosk runtime, глобальной горячей клавиши и запуска целей макросов.
3. Реализовать отдельные аудиобэкенды: WinMM/WASAPI для Windows, ALSA/PulseAudio или PipeWire для Linux, CoreAudio для macOS.
4. Подключить отдельные Vosk runtime и проверить лицензии/зависимости для каждой архитектуры.
5. Создать нативные UI-бэкенды либо заменить UI на переносимый GUI-фреймворк. Системные виджеты и панели требуют отдельных реализаций.
6. Добавить CI-сборки на реальных runner-образах каждой ОС, затем провести аппаратные тесты с микрофонами и проверить установку/запуск пакетов.

## Что считается завершением проверки

- CI конфигурирует, компилирует и упаковывает целевую архитектуру.
- В артефакте присутствуют runtime и языковая модель нужной архитектуры.
- Приложение реально запускается на заявленной версии ОС.
- Микрофон открывается, речь распознаётся, Push-to-Talk и макросы работают.
- Проверены отключение/повторное подключение микрофона, длительное прослушивание и корректное завершение приложения.

Успешная CI-сборка не заменяет проверку на физическом компьютере.
